# Module 13 – Agile Methodology — Hands-on Practice

Covers: Agile Manifesto, Scrum roles/ceremonies/artifacts, estimation techniques
(story points, planning poker), sprint planning, user stories, and acceptance criteria.

## What's included
Two fill-in templates you'll use repeatedly on real projects:
- `templates/user-story-template.md`
- `templates/sprint-planning-template.md`

## Problem Statements

### 1. Write 5 user stories
Using `templates/user-story-template.md`, write 5 user stories for the
`ProductCatalogAPI` you built in Module 6 (e.g., "As a shopper, I want to search
products by name..."). Make sure each follows the INVEST principle:
- **I**ndependent
- **N**egotiable
- **V**aluable
- **E**stimable
- **S**mall
- **T**estable

### 2. Add acceptance criteria
For each story, write acceptance criteria in Given-When-Then format. Example:
```
Given a shopper on the product listing page
When they type "keyboard" into the search box
Then only products containing "keyboard" in the name are shown
```

### 3. Estimate with story points
Assign story points (use the Fibonacci-like scale: 1, 2, 3, 5, 8, 13) to each of your
5 stories, as if you were playing Planning Poker with a team. Write a one-line
justification for your two largest estimates — why are they bigger than the rest?

### 4. Plan a sprint
Using `templates/sprint-planning-template.md`, put your 5 stories into a 2-week sprint.
Assume your (imaginary) team's velocity is 15 points from the last sprint — does
everything fit? If not, decide what to defer to the next sprint and why.

### 5. Scrum roles and ceremonies — explain in your own words
Write 1-2 sentences each on:
- What the **Scrum Master** is responsible for (vs. what they are NOT responsible for)
- What the **Product Owner** decides vs. what the **Dev Team** decides
- The difference between **Sprint Review** and **Sprint Retrospective** (these are
  commonly confused)

### 6. (Stretch) Draw a burndown
On paper or in a spreadsheet, sketch what an *ideal* burndown chart looks like for your
15-point sprint over 10 working days, then sketch a *realistic* one showing a team that
gets stuck for 2 days on one story before catching up.

## Check your understanding
Be able to explain, in one sentence, the difference between Agile and Waterfall in
terms of *when* the customer gets to see working software.
